# Парсеры для аутрича StepToLead — план, контекст, правила

Документ для того, кто будет делать (новый чат Claude — бэкенд, Codex — экран). Читать целиком перед работой.

## 1. Что уже есть (не делать заново)

Портал: FastAPI + SQLAlchemy async (Postgres в проде, SQLite в тестах), Next.js/TypeScript. Схема — `create_all` + `backend/app/db_upgrade.py` (ALTER колонок), без alembic. Админка агентства: `require_admin`, рабочее пространство агентства — `settings.agency_workspace_id`.

Лидогенерация — `backend/app/domains/leadgen/`:
- **Поиск компаний** (`direct_search.py`, `providers.py`): рекламодатели Яндекс Директа и топ-10 органики по ключам и региону через XMLStock (ключи только из окружения). Запуск — `LgSourceRun` (source: yandex_direct / yandex_organic / twogis / hh / import).
- **Компания** — `LgCompany` (инн, домен, город, регион, ниша, ОКВЭД, директор, выручка, статус юрлица, fit ИИ, score, stage, provenance), ключи дедупликации `LgCompanyKey` (ИНН / домен / телефон / 2ГИС id / hh id), контакты `LgContact` (kind phone/whatsapp/telegram/email/vk/form_url, `is_personal`, verify_status, bounced).
- **Вход для любого источника**: `service.FindingIn` → `service.upsert_company(db, workspace_id, finding)` (дедуп по ключам, не коммитит). Сигнал — `service.add_signal(db, company, kind, key=, payload=, run_id=)` (пересчитывает score). Сигналы с TTL — `LgSignal.expires_at`.
- **Веса сигналов** — `core/scoring.py` (WEIGHTS) и подписи на экране — `frontend/app/admin/leadgen/shared.tsx`. Уже есть: ad_direct, ad_premium, new_advertiser, ads_stopped, has_messenger, site_quiz, no_crm, legal_active, organic_only, hh_marketing, hiring (радар вакансий), twogis_card, slow_response, organic_top, merged.
- **Обогащение**: `site_enrich.py` (обход сайта с robots.txt: контакты, ИНН, квиз, мессенджеры, CRM-виджеты; личные почты отсекаются), `dadata.py` (юрлицо по ИНН), `fit_ai.py` (ИИ «подходит / возможно / нет» по портрету клиента).
- Списки, импорт таблиц, выгрузка, цепочки писем, прогрев, входящие, «горячие» ответы — работают, не трогать.

Готовые универсальные куски из радара вакансий (переиспользовать, не копировать):
- `backend/app/domains/jobradar/sources/` — **контракт адаптера площадки** (`Adapter`: code, title, icon, purpose, needs_key, key_field, settings_schema, default_enabled, unit_seconds, concurrency, units(), ready(), fetch(), healthcheck()), реестр `sources/__init__.py`, `Context` (http с прокси, sleep, cache, on_request-хук), `limited()` — параллельно с лимитом и паузой, `short_error()` — короткие ошибки без адресов.
- `backend/app/domains/jobradar/platforms.py` — настройки площадок в БД, секреты зашифрованы (`<key>_encrypted`), публичный вид без секретов, проверка «Проверить».
- `backend/app/services/progress.py` — прогресс любой долгой операции (шаги, параллельные группы, проценты, «осталось ≈»). `backend/app/domains/jobradar/timing.py` — оценка времени до запуска, обучается по факту.
- `frontend/components/task-progress.tsx` — `EstimateHint` («⏱ Займёт ≈ 30 с») и `TaskProgress` (полоса, шаги).
- Экран плашек площадок: `frontend/app/admin/jobradar/sources-panel.tsx`, `source-settings.tsx`.

## 2. Идеи: какие парсеры и сигналы добавить

ЦА: частный B2C-бизнес (ООО/ИП), 1–5 филиалов в регионе, чек от 50 000 ₽, крутит рекламу. Ниши: ремонт, дома и бани, кухни и мебель на заказ, окна и потолки, загородная инженерия, стоматология, косметология, банкротство физлиц. Город и регион не зашиты — их выбирают в каждом поиске. Не пишем: сети, франшизы, B2B, госы, агентства-конкуренты. Боль: не понимают, какая реклама окупается; заявки теряются.

### Этап 1 — быстро и с наибольшей отдачей

**1. Тех-профиль сайта** (расширить `site_enrich`, без новых внешних API)
- Что ищем в HTML: Яндекс Метрика (номер счётчика), Google Analytics, коллтрекинг (Calltouch, CoMagic, Roistat, Mango, Callibri), онлайн-чат (Jivo, Битрикс24, Talk-Me), CRM-формы (amoCRM, Битрикс24), квиз (Marquiz, есть), платформа (Тильда, WordPress, 1С-Битрикс), год в подвале, политика ПДн.
- Скорость мобильной версии — Google PageSpeed Insights API (бесплатный ключ в настройках портала; без ключа — пропуск).
- Сигналы: `no_analytics` (нет Метрики — не видят, откуда заявки — прямо наша боль), `no_calltracking`, `slow_site`, `outdated_site` (год в подвале старше 2 лет), `has_calltracking` (продвинутый покупатель, другой текст письма).
- Переменные для письма: `{{site_platform}}`, `{{has_metrika}}`… чтобы первое письмо было по делу («звонки с рекламы у вас не размечены»).

**2. Реестр МСП ФНС + выручка из ГИР БО** (открытые данные ФНС)
- Реестр субъектов МСП (rmsp.nalog.ru, открытые данные): компании по ОКВЭД ниши и региону, категория (микро / малое / среднее), дата включения. Это база ниши с ИНН без серых парсеров.
- ГИР БО (bo.nalog.ru): выручка за прошлый год у ООО → квалификация (например, 10–500 млн) и отсев гигантов. Формат и ограничения выгрузки — проверить живым запросом.
- Сайт компании находим поиском «название + город» через уже подключённый XMLStock (органика), дальше обычный `site_enrich`.
- Сигналы: `new_company` (зарегистрирована < 12 мес — нужен маркетинг с нуля), `revenue_fit` (выручка в целевом коридоре), `msp_small`.

**3. Отзывы как сигнал боли «теряют заявки»**
- ИИ размечает отзывы о компании: «не перезвонили», «долго отвечали», «не ответили в WhatsApp» → сигнал `lost_leads_reviews` (сильный, бьёт ровно в боль, которую закрывает CRM портала).
- Источник отзывов — только разрешённый: 2ГИС API (отзывы — отдельный доступ, уточнить у 2ГИС) или ручной импорт. В письме отзывы не цитируем и людей не называем, только «судя по отзывам, часть клиентов не дожидается ответа».

### Этап 2

**4. 2ГИС Places API** (официальный ключ; демо-ключ есть, дальше подписка)
- Карточки по рубрике и городу: филиалы (отсев сетей: > 5 филиалов), сайт, рубрики, рейтинг. Контакты (`contact_groups`) отдаются по отдельному разрешению — запросить у 2ГИС. До ответа 2ГИС по условиям хранения в базу не пишем ничего, кроме ссылки/id.
- Сигнал `twogis_card` уже есть.

**5. ВКонтакте — сообщества компаний** (официальный VK API, сервисный ключ)
- Поиск групп «ниша + город», подписчики, дата последнего поста, открыты ли сообщения, ссылка на сайт → склейка с компанией по домену/телефону.
- Сигналы: `vk_active` (ведут соцсети — бюджет на маркетинг есть), `vk_abandoned` (последний пост > 3 мес — повод предложить SMM).

**6. Новые сайты ниши** — списки новых доменов .ru/.рф (публичные ежедневные списки регистраций) с нишевыми словами + город на сайте → сигнал `new_site` (сайт запустили — нужен трафик). Проверить, какой список доступен легально.

**7. Директ по расписанию** — повторные прогоны «Поиска компаний» по сохранённым ключам раз в неделю (как радар), чтобы сигналы `new_advertiser` / `ads_stopped` приходили сами.

### Не делаем
- Яндекс Карты / API поиска по организациям Яндекса — условия запрещают хранить результаты (п. 2.1–2.2: только кэш до 30 дней для скорости, показ только на карте Яндекса).
- Парсинг Авито, Профи, ПроДокторова и других сайтов, чьи правила запрещают сбор; API Авито — только для своего аккаунта.
- Личные данные сотрудников (ФИО + личные телефоны/почты). Пишем только на общие адреса компании.

## 3. Архитектура (универсально, по образцу радара)

Один механизм на все источники — «Источники компаний» с плашками, как площадки радара:

- `backend/app/domains/leadgen/sources/` — контракт `CompanySource` по образцу `jobradar.sources.Adapter` (те же поля + `kind`: `finder` — даёт новые компании, `enricher` — дополняет существующую). Реестр, `ORDER`, `ADAPTER` в каждом модуле. Общие `Context`, `limited`, `short_error` — импортировать из радара или вынести в `app/services/` (без поломки радара).
- `finder.fetch(query, settings, ctx) -> list[Candidate]`, где `Candidate` = поля `FindingIn` + `signals: list[(kind, key, payload, ttl_days)]` + `source_url`. Раннер сам делает `upsert_company` + `add_signal`, дедуп по ИНН/домену/телефону, `provenance` поля → источник.
- `enricher.enrich(company, settings, ctx) -> Enrichment` (поля компании, контакты, сигналы). Только общие контакты; `is_personal=True` — не сохранять как контакт для рассылки.
- Настройки источников в БД, секреты зашифрованы — тем же способом, что `jobradar/platforms.py` (переиспользовать). Ключи — только через экран портала, не в коде и не в `.env`.
- Запуск — `LgSourceRun` (source = код источника), прогресс — `app/services/progress.py`, оценка — по образцу `jobradar/timing.py`, на экране — `components/task-progress.tsx`.
- Новые сигналы — в `core/scoring.py` (WEIGHTS) и `frontend/app/admin/leadgen/shared.tsx` (подписи).
- Контракт API для экрана — файл `backend/app/domains/leadgen/SOURCES.md` (пишет бэкенд первым, по образцу `jobradar/SOURCES.md` и `SCANNERS.md`).

## 4. Правила (обязательно)

- Никаких токенов и ключей в коде, тестах и коммитах — только через настройки портала. `.env` / `.env.prod` не трогать и не печатать.
- Не менять существующую логику поиска, цепочек, прогрева, входящих, CRM и радара — только точки подключения (вызов нового источника, новые сигналы, новые веса).
- robots.txt, паузы и лимиты одновременных запросов (как `limited` в радаре); при 429 — пауза и повтор позже, не долбить.
- Тесты — на сохранённых образцах ответов (fixtures), без сети. Живые образцы обезличить (без телефонов/почт людей).
- Ошибки на экране — короткие, по-русски, без адресов и параметров запросов.
- Интерфейс — по-русски. Коммит и пуш — только когда попросит Егор.

## 6. Разделение и порядок

| Часть | Кто |
|---|---|
| Контракт источников, раннер, настройки, источники этапа 1, сигналы, веса, тесты, `SOURCES.md` | Claude (бэкенд) |
| Экран «Источники компаний»: плашки с настройками и «Проверить», запуск поиска по источнику с оценкой и прогрессом, новые сигналы и переменные в карточке компании и фильтрах списков | Codex (экран) |

Порядок: (1) контракт + раннер + перенос тех-профиля сайта в `enricher`; (2) реестр МСП + ГИР БО; (3) отзывы (после ответа 2ГИС по доступу); затем этап 2. После каждого шага — тесты, `tsc`, живая проверка на тестовом стенде и короткий отчёт Егору с командами заливки.
