# Рабочее место базы (список компаний) — как у Polza

Цель: клик по списку на «Списках и выгрузках» открывает **отдельный экран базы**: таблица на всю ширину, вкладки
открытых баз, панель кнопок-функций. Функции можно выбрать сразу несколько и запустить одной кнопкой по
отмеченным строкам или по всей базе. Ориентир — экран «Базы» в Polza.

Все пути API — `/api/admin/leadgen`. Контракт источников — `SOURCES.md`, этот файл его дополняет. Город по
умолчанию нигде не подставляется.

## 1. Экран `/admin/leadgen/lists/{id}`

Экран «Списки и выгрузки» не меняется, кроме одного: клик по названию списка ведёт сюда, а не в общую базу.

**Шапка:**
- «← Все списки»;
- вкладки недавно открытых баз (до 8, хранятся в localStorage, крестик закрывает вкладку);
- название базы — редактируется по клику;
- счётчики: всего, с почтой, с проверенной почтой, подходят (ИИ), не выгружались.

**Панель функций (обогащение).** Кнопки-переключатели — выбираешь несколько, затем **«▶ Запустить выбранное (N)»**:

| Кнопка | Код | Что делает |
|---|---|---|
| Найти сайт и ИНН | `find_site` | есть |
| Найти почты | `site_contacts` | есть (сбор контактов с сайта) |
| Валидация почт | `email_check` | есть |
| Чистка названий | `name_clean` | есть |
| Проверка сайтов | `site_tech` | есть (тех-профиль) |
| DaData | `dadata` | **новый** — реквизиты по ИНН: юрлицо, ОКВЭД, директор, статус |
| Доходы ФНС | `fns_revenue` | **новый** — выручка из бухотчётности ФНС |
| Оценка ЦА | `fit_ai` | **новый как источник** — обёртка над существующей ИИ-оценкой |
| Персонализация | `personalize` | **новый** — ИИ-строка для письма |

Как работает запуск:
- Порядок выполнения — всегда как в таблице выше, независимо от порядка нажатия: сначала сайт и ИНН, потом почты, потом проверка.
- До запуска рядом с кнопкой видно «⏱ Займёт ≈ … · Запросов к поиску: N (≈ X ₽) · ИИ: ≈ N токенов».
- **Область:** «Отмеченные (N)» или «Вся база (N)».
- Во время работы — `TaskProgress` с шагами. После — итог по каждой функции и обновлённая таблица.
- Набор нажатых кнопок запоминается для базы (localStorage).

**Панель действий:**
- В кампанию…
- В CRM
- В другой список…
- На проверку
- Скрыть
- Удалить
- Excel
- CSV
- Копировать (выбранные строки в буфер как TSV)
- Импорт в эту базу

**Над таблицей:**
- переключатель «Совпадения» — подсвечивает возможные дубли;
- поиск по всем колонкам;
- «Колонки» — какие показывать, порядок, запоминается;
- «Перенос строк: вкл/выкл».

**Таблица:**
- колонки: ☐, компания, сайт, ИНН, город, ниша, почта (лучшая + значок статуса ✓ ⚠ ✕ + «ещё N»), телефон, мессенджеры, сигналы (чипы), ИИ (подходит / возможно / нет), скоринг, выручка, стадия, источник, добавлена;
- в шапке каждой колонки — фильтр: текст «содержит», «пусто / не пусто»; для статусов и сигналов — выбор значений;
- сортировка по клику на заголовок;
- **правка ячейки по двойному клику:** название, сайт, ИНН (с проверкой контрольной суммы), город, ниша. Источник правки — `manual`, автоматическая чистка его больше не трогает;
- клик по строке открывает существующую карточку компании справа;
- страницы по 100, отметка «выбрать все на странице / всю базу».

**Правая панель** (сворачивается):
- **«Сводка»** — выбор колонки (город, ниша, домен, источник, сигнал, оценка ИИ, статус почты, стадия) → список «значение — сколько». Клик по значению ставит фильтр. Сверху «Всего: N».
- **«Очистка»** — быстрые наборы:
  - скрыть без почты;
  - скрыть с невалидной почтой;
  - скрыть «не подходит» по ИИ;
  - скрыть сети (больше N филиалов или выручка выше порога);
  - отправить дубли на проверку.

  Каждый набор сначала показывает «затронет N компаний», применяется по подтверждению.

Ширина 390 px: таблица прокручивается внутри своего блока, страница не шире экрана.

## 2. API

```
GET  /lists/{id}/table?q=&sort=&dir=&page=&per_page=100&f.<колонка>=<условие>…
  → {"total", "items": [Row], "columns": [{"key","label","filter": "text"|"values"|"empty"}]}
  Row = company_row + {"best_email": {"value","verify_status"}|null, "emails": int, "phone", "messengers": [kind],
                       "signals": [kind], "revenue_rub", "source", "added_at", "duplicate_group": str|null}
  // f.city=contains:самар, f.domain=empty, f.email_status=in:valid,risky, f.signal=in:hiring …

GET  /lists/{id}/summary?column=city|niche|domain|source|signal|fit|email_status|stage
  → {"total", "items": [{"value", "count"}]}

POST /lists/{id}/run  {"steps": [code…], "company_ids"?: [int]}     // без company_ids — вся база
  → 202 {"run_id"}   // тот же раннер, прогресс и итог, что у цепочки (result.chain); 409 если по базе уже идёт запуск
POST /lists/{id}/estimate {"steps", "company_ids"?} → {"seconds", "steps", "cost"?, "ai_tokens"?}

PATCH /companies/{id} {"display_name"?, "domain"?, "inn"?, "city"?, "niche"?}
  → company_row   // provenance=manual; ИНН с неверной контрольной суммой — 422; конфликт ИНН или домена с другой компанией — 409 с её id
POST /companies/review {"company_ids", "reason"?}   → {"updated"}   // needs_review = "manual:<reason>"
POST /companies/review/clear {"company_ids"}        → {"updated"}

GET  /companies/export?…&format=csv   // как xlsx, но CSV (UTF-8 с BOM, разделитель ;)
POST /lists/{id}/cleanup/preview {"rule": "no_email"|"bad_email"|"not_fit"|"chains"|"duplicates", …параметры}
  → {"count", "sample": [Row]}
POST /lists/{id}/cleanup {"rule", …} → {"updated"}   // скрыть (stage=hidden) или на проверку — для duplicates
```
- **Совпадения:** `duplicate_group` — одинаковый телефон, или одинаковое нормализованное название в одном городе, или один домен у разных записей. Только подсветка, склейка — существующим «объединить».
- `fit_ai`, `dadata`, `site_contacts` — обёртки над существующей логикой (`fit_ai.py`, `dadata.enrich_legal`, `site_enrich`). Логику не менять.

## 3. Новые источники

**`dadata`** (enricher) — для компаний с ИНН. Существующий `dadata.enrich_legal`: юрлицо, ОКВЭД, директор, статус, адрес. Ключ — настройка DaData портала. Нет ключа — `ready_reason`.

**`fns_revenue`** (enricher) — выручка за последний год из ГИР БО ФНС (bo.nalog.ru) по ИНН.
- Формат и ограничения открытого API **сначала проверить живым запросом** и сохранить обезличенный образец в fixtures. Не угадывать: если API недоступен — сказать в отчёте.
- Пишет `revenue_rub` и `revenue_year`.
- Сигнал `revenue_fit`, если выручка в коридоре из настроек источника (`revenue_min`, `revenue_max`, по умолчанию 10–500 млн).
- Сигнал `big_company`, если выше максимума — для очистки «сети».
- Паузы между запросами и лимит параллельности — вежливо.

**`fit_ai`** (enricher) — обёртка над существующей «Оценить ИИ», чтобы она была кнопкой панели и шагом цепочки.

**`personalize`** (enricher) — ИИ пишет **одну первую строку письма** (до 200 символов) по фактам компании:
- реклама (`LgAd`), сигналы (вакансия, тех-профиль: нет Метрики или коллтрекинга), ниша, город, заголовок сайта;
- только факты из базы, без выдумок; если фактов нет — `skipped` («мало данных»);
- результат — `lg_enrichments(step="personalize").result = {"line", "facts": [...]}`;
- в карточке и в таблице (колонка «Персонализация», скрыта по умолчанию) — строку можно поправить руками;
- расход — резерв ИИ агентства (bucket `agency`), модель на экране не называется.

**Переменные в письмах.** Сейчас `sequences._context` не видит переменные источников (`variables` у `site_tech`), поэтому `{{site_platform}}` и другие не подставляются. Добавить в контекст письма значения из `lg_enrichments.result` всех источников с `variables`, плюс `{{personal_line}}` из `personalize`. В редакторе цепочки они должны появиться в списке переменных.

## 4. Тесты и проверка

- Тесты на каждый новый эндпоинт и источник: образцы ответов без сети, ИИ подменяется.
- Тесты на фильтры колонок, сводку, очистку (preview = apply), правку ячейки (manual не перетирается чисткой), CSV.
- Прогон: `test_leadgen*`, `test_jobradar*`, `tsc`, `frontend/tests`, production-сборка.
- Не менять существующую логику поиска, сбора контактов, рассылок, CRM и радара — только точки подключения. Ключи только через настройки портала, `.env` не трогать.
