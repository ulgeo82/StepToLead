# StepToLead Portal

Локальный портал агентства: публичный калькулятор экономики роста, защищённая админка, клиентские пространства, рекламные кабинеты и Telegram Outreach.

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

- Интерфейс: http://localhost:3000
- API: http://localhost:8000
- Документация API: http://localhost:8000/docs

Первичный администратор создаётся локальной командой и не регистрируется через интернет:

```bash
docker compose exec backend python -m app.setup_admin --bootstrap-file /app/.admin-access.txt
```

После этого данные входа находятся в приватном файле `backend/.admin-access.txt`. Файл исключён из Git.

## Рекламные кабинеты

Раздел **Админка → Реклама** поддерживает реальные подключения:

- Яндекс Директ: OAuth-токен и `Client-Login`;
- Meta Ads: access token с правом чтения статистики и ID вида `act_...`.

Пароли от рекламных кабинетов портал не принимает. Токены шифруются с помощью `ENCRYPTION_SECRET`, не возвращаются через API и используются только сервером. Кнопка **Проверить** обращается к официальному API, а **Синхронизировать** загружает дневные расходы, показы, клики и лиды за последние 30 дней.

Для разработки через Docker никаких глобальных зависимостей, кроме Docker Desktop, не требуется. API также допускает временный локальный `DATABASE_URL=sqlite+aiosqlite:///...` для разработки интерфейса без контейнеров; основное окружение в Compose всегда использует PostgreSQL.

## Формат импорта

CSV или XLSX должен содержать колонки `username` и `first_message`. Заголовки нечувствительны к регистру и пробелам. Username можно указывать с `@` или без него; дубликаты в рамках одной кампании пропускаются.

## Ручная отправка

Откройте раздел **Очередь**, выберите лида и нажмите **Написать**. Кнопка **Открыть Telegram** копирует подготовленный текст и открывает чат `t.me/username`. После фактической отправки нажмите **Готово, отправлено**. Текст можно отредактировать в окне отправки — новая версия сохранится в базе.

## Архитектура расширения

Backend разделён на `models`, `schemas`, `routes` и `services`. Новые домены — Telegram Accounts, Proxies, Inbox, AI Settings — можно добавлять отдельными моделями и маршрутами, не меняя существующий импорт лидов. Redis уже включён в окружение для будущих очередей отправки и обработки входящих сообщений.

## Подключение Telegram API

1. Получите собственные `api_id` и `api_hash` в разделе **API development tools** на https://my.telegram.org.
2. Добавьте значения в `.env`:

```env
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=your_api_hash
ENCRYPTION_SECRET=your-long-random-secret
```

Секрет можно создать командой `openssl rand -hex 32`. Не отправляйте `api_hash`, коды входа, пароль 2FA или Telegram-сессии в чат. После изменения `.env` перезапустите проект командой `docker compose up --build --force-recreate`.

Раздел **Прокси** принимает SOCKS5, SOCKS4 и HTTP в форматах `scheme://user:password@host:port`, `host:port:user:password` и `host:port`. Пароли прокси и Telegram-сессии сохраняются в базе только в зашифрованном виде.

## Массовый импорт tdata

В разделе **Telegram-аккаунты** нажмите **Импорт tdata** и выберите сразу несколько ZIP-файлов. Один ZIP должен содержать папку `tdata` одного аккаунта; архив может содержать её напрямую или внутри общей папки. За один импорт поддерживается до 50 архивов размером до 100 МБ каждый. Результат показывается отдельно для каждого файла, поэтому ошибка одного аккаунта не прерывает остальные.

Поддерживаются активные tdata-сессии без локального пароля Telegram Desktop. Архивы распаковываются только во временную папку и удаляются после обработки; в базе остаётся зашифрованная сессия. Импортируйте только принадлежащие вам аккаунты и не передавайте ZIP-файлы третьим лицам.

## Telegram через зарубежный сервер

С 2026 года российские провайдеры блокируют `api.telegram.org` с серверов в РФ. Портал и база остаются в России (152-ФЗ), а запросы ботов — служебного бота уведомлений и клиентских ботов (1 клиент = 1 бот) — идут через небольшой сервер за рубежом. Посредник ничего не хранит: токены, переписка и база остаются в портале. Входящие сообщения портал забирает сам опросом через посредника, поэтому Telegram не нужно достучаться до российского сервера. Telegram-аккаунты для рассылок и парсинга используют свои прокси из раздела «Прокси», эти настройки на них не влияют. WhatsApp, Авито и остальные каналы ходят напрямую.

Вариант 1 — обратный прокси (рекомендуется). На зарубежном VPS с доменом `tg-relay.example.com` в Caddyfile:

```
tg-relay.example.com {
    @foreign not remote_ip IP_РОССИЙСКОГО_СЕРВЕРА
    respond @foreign 403
    reverse_proxy https://api.telegram.org {
        header_up Host api.telegram.org
    }
}
```

В `.env` портала: `TELEGRAM_API_BASE=https://tg-relay.example.com`.

Вариант 2 — обычный прокси (HTTP или SOCKS5, например 3proxy или dante на зарубежном VPS): `TELEGRAM_PROXY=socks5://user:pass@host:1080`. Можно сочетать с вариантом 1.

После смены настроек перезапустите backend. Проверка: «Мониторинг» → «Telegram» → «Отправить тест», или `curl https://tg-relay.example.com/bot<токен>/getMe` с российского сервера.

## Telegram-бот

**Настройки → Уведомления** — для событий «Новый лид» и «Новая продажа» в каждом проекте выбирается:

- кому: по умолчанию (ответственный за лид, иначе собственник и руководители продаж проекта) или конкретные участники проекта, плюс опция «уведомлять ответственного»;
- куда: в кабинет StepToLead и/или в Telegram.

Уведомление о новом лиде приходит при ручном создании лида и при каждой заявке из интеграций (Tilda, входящий API). Автор действия уведомление о своём действии не получает.

Чтобы включить Telegram:

1. Человек создаёт в @BotFather бота «StepToLead Уведомления» командой `/newbot`. Токен хранится только в `TELEGRAM_BOT_TOKEN` на сервере. Для разработки создайте **другого тестового бота**: боевой токен локально не используйте, даже с отдельной БД/Redis.
2. Нужны `REDIS_URL` (общий Redis для всех процессов backend) и корректный `FRONTEND_ORIGIN` — публичный HTTPS-адрес портала для кнопок. Эти переменные уже есть в примерах окружения и Compose. После настройки перезапустите backend; без токена обработчик не запускается.
3. Каждый сотрудник в **Настройки → Уведомления → Мой Telegram** нажимает «Подключить Telegram» и Start в боте. Статус обновляется автоматически каждые 3 секунды до 2 минут; «Проверить» только читает состояние. Администратор агентства подключает Telegram отдельно в **Админка → Мониторинг**. Старые привязки сохраняются.
4. В правиле уведомления отметьте канал «Telegram».

Один фоновый обработчик читает `getUpdates` с timeout=25. Redis-блокировка с продлением выбирает единственного обработчика среди процессов; при недоступном Redis обработчик ждёт восстановления, а не начинает конкурирующий опрос. Offset и последние 200 update_id сохраняются в `app_settings` в одной транзакции с действием CRM. Публичный webhook не нужен: не устанавливайте этому боту webhook. Не используйте его токен в CRM → Чаты — для клиентской переписки нужны отдельные боты.

Команды: `/menu` — доступные проекты и портал, `/leads` — новые заявки и сделки (по 5), `/tasks` — свои открытые задачи: просроченные, сегодня и завтра; `/report` — отчёт за 7/30 дней из аналитики портала; `/settings` — личные уведомления, телефон и тихие часы. Выбор проекта и настройки сохраняются в `portal_users.telegram_state` (аддитивная колонка JSON, добавляется при запуске backend). Часы зависят от часового пояса проекта, перенос «на завтра» — на 10:00. Тихие часы подавляют доставку, не откладывают её; уведомление в кабинете остаётся. Личные настройки только сужают правила проекта. Телефон по умолчанию скрыт.

Кнопки заявки: взять в работу, отметить нецелевой с причиной, создать задачу на перезвон через час/завтра, открыть сделку в портале. Задачи можно выполнить с быстрым результатом или перенести. Каждый callback проверяет актуальные права, компанию, проект и владельца; изменения записываются в историю от имени сотрудника с пометкой «через Telegram». Повторный update_id не повторяет действие. Бот работает только в личных чатах. Администратору агентства доступно отдельное меню сбоев и фоновых задач без CRM клиентов. В открытой сделке доступен звонок через Mango, если подключена телефония и сотруднику назначен внутренний номер АТС; используется то же ядро, что в API портала. Запрос звонка — внешний эффект: при обрыве соединения с АТС проверьте журнал звонков перед повторной попыткой.

Проверка на тестовом боте: запустите backend с отдельным токеном и Redis, подключитесь через настройки, дождитесь автоматического подтверждения, откройте `/menu`, отправьте тестовую заявку и нажмите «Перезвонить через 1 ч». Проверьте задачу и историю сделки в CRM, затем выполните задачу кнопкой. Для менеджера проверьте, что чужие проекты/сделки недоступны. В мониторинге должна работать задача «Telegram-бот». При блокировке бота пользователем привязка снимается; ошибки сети/429 повторяются без остановки обработчика.

Автотесты без Telegram и Redis: `cd backend && PYTHONPATH=. python3 -m unittest discover -s tests -p 'test_tg_bot.py'`. Все обращения к Telegram подменяются моками; `.env` тесты не меняют.

## Авито

В разделе **Реклама → Подключить рекламу** есть две отдельные платформы.

**Авито · Объявления** (классифайд). Ключи: avito.ru/professionals/api → «Получить ключи» (Client ID и Client Secret; нужен профиль компании). ID профиля определяется автоматически.

- Синхронизация: расходы на размещение и продвижение (только деньги, бонусы отдельно), показы, просмотры, контакты (телефон и чат) по дням. Первая синхронизация берёт 270 дней (максимум API), следующие перечитывают последние 30.
- Карточка кабинета: баланс и бонусы, таблица объявлений за период (показы, просмотры, CTR, контакты, конверсия, расход, цена контакта, заявки в CRM). Авито разрешает 1 запрос статистики в минуту, поэтому таблица загружается по кнопке и кэшируется на 10 минут.
- **Заявки → CRM**: включаются галочками «Чаты» и «Звонки». Каждый новый чат по своему объявлению и каждый звонок становятся заявкой во «Входящих» CRM (имя, объявление, первое сообщение, ссылка на чат / номер, запись звонка). Звонки приходят через Коллтрекинг Авито, а если он не подключён, через CPA. Если нет ни того, ни другого, портал покажет предупреждение. Принятая заявка засчитывается этому кабинету, поэтому CPL и ROMI Авито считаются по реальным лидам.

**Авито Реклама** (баннеры и видео, ads.avito.ru). Ключи создаёт администратор во вкладке «API» кабинета, плюс нужен числовой ID аккаунта.

- Синхронизация: кампании и статистика по дням (показы, клики, расход в рублях с НДС; бонусы хранятся отдельно). Первая синхронизация берёт 365 дней кусками по 100 дней. Каждый запрос статистики тратит 10 API-баллов Авито, баллы обновляются по понедельникам.
- Карточка кабинета: баланс и таблица кампаний (статус, модель оплаты, показы, клики, CTR, расход, CPC, CPM). Страница кампании показывает статистику по дням, группам и креативам с превью и ссылками.

Фоновый процесс backend каждые 3 минуты забирает новые чаты и звонки, а раз в 6 часов обновляет статистику подключённых кабинетов Авито (после первой ручной синхронизации).

## CRM

Раздел **CRM** (`/crm`) — продажи в одном месте с рекламой и аналитикой.

- **Сделки:** канбан и список, несколько воронок, суммы по этапам, «дней на этапе», подсветка сделок без движения 3+ дня. Фильтры: менеджер, источник, тег, «Мои», «Без движения»; поиск по сделке, имени, телефону, email. Массовые действия в списке: этап, ответственный, тег, архив. Выгрузка в CSV (Excel).
- **Карточка сделки:** этапы кликабельной лентой, быстрые действия (позвонить, WhatsApp, Telegram, email, чат Авито), поля и теги, атрибуция рекламы, исходная заявка, задачи, продажи и человеческая лента событий с примечаниями, звонками, сообщениями и встречами. Видна скорость реакции на лид.
- **Задачи:** при завершении задачи сразу ставится следующая; быстрые сроки (15 мин, час, завтра, 3 дня, неделя).
- **Контакты:** карточка клиента со всеми сделками, LTV, заметками и тегами, редактирование и склейка дублей (телефоны 8… и +7… считаются одинаковыми).
- **Неразобранное:** заявки с сайта, Авито и интеграций показывают время ожидания; их можно принять, связать с существующим клиентом или отклонить с причиной.
- **Автоматизация (digital pipeline):** правила «новая сделка», «переход на этап» и «нет активности N времени» с действиями: задача, ответственный (в том числе по очереди), тег, уведомление в кабинет и Telegram. Кнопка «Рекомендуемые правила» ставит стартовый набор. Правила без активности проверяются фоновым процессом каждые 10 минут.
- **Аналитика продаж:** когорта сделок за период: воронка с конверсиями, win rate, выручка, средний чек, цикл сделки, скорость реакции (медиана и доля «за 15 минут»), менеджеры, источники, причины отказов и прогноз выручки по исторической вероятности этапов.

## Переписки (CRM → Чаты)

Все диалоги с клиентами собраны в одном окне. Ответ уходит в тот же мессенджер, а в сделке сохраняется вся история.

- **Каналы** (CRM → Чаты → «⚙ Каналы»):
  - **Telegram-бот** — отдельный бот компании от @BotFather (не бот уведомлений).
  - **WhatsApp** — через GREEN-API (idInstance, apiTokenInstance, apiUrl; номер привязывается QR-кодом).
  - **Чаты Авито** — используют ключи кабинета «Авито · Объявления»; ответ до 1000 символов.
- Первое сообщение от нового человека становится заявкой в «Неразобранном». При принятии заявки диалог привязывается к клиенту и сделке. Если телефон уже есть в CRM, диалог сразу подтягивается к этому клиенту.
- Фильтры: «Ждут ответа» (с временем ожидания, после 15 минут подсвечивается красным), «Непрочитанные», «Без ответственного», «Мои». Можно назначить ответственного, закрыть диалог и пользоваться шаблонами быстрых ответов.
- В карточке сделки есть блок «Переписка». В WhatsApp клиенту можно написать первым; Telegram-бот и Авито первыми писать не позволяют.
- Ответ менеджера засчитывается как касание: от него считается скорость реакции. О новом сообщении ответственный получает уведомление в кабинете и в Telegram.
- Опрос каналов идёт в фоне: Telegram и WhatsApp каждые 15 секунд, Авито раз в минуту. Публичный webhook не нужен.

## Телефония (CRM → Звонки)

Подключена Mango Office (VPBX API). Настройка — кнопка «⚙ Подключить телефонию» во вкладке «Звонки» (руководитель или владелец):

1. В кабинете Mango: «Интеграции → API-коннектор» — скопировать «уникальный код АТС» и «ключ для создания подписи», вставить в портал. Портал проверяет ключи запросом списка сотрудников.
2. Портал показывает адрес для событий `https://<домен>/api/telephony/mango/<секрет>` — его вставляют в «Адрес внешней системы» в Mango. Mango шлёт события на `<адрес>/events/call|summary|recording`, каждое подписано `sha256(vpbx_api_key + json + salt)`; неподписанные запросы отклоняются (403).
3. Сопоставить внутренние номера АТС с сотрудниками (совпадающие имена подставляются сами).

Что происходит со звонком:
* `events/call` — живое состояние: всплывающая карточка «Входящий звонок» у менеджера (опрос `/calls/active` раз в 3 с), с клиентом и сделкой.
* `events/summary` — итог: звонок привязывается к контакту/открытой сделке по телефону (8… и +7… считаются одним номером) и попадает в историю сделки. Незнакомый входящий номер → заявка в «Неразобранном» (можно выключить). Пропущенный входящий → задача «Перезвонить +7 …» ответственному (срок настраивается, по умолчанию 15 минут) и уведомление. Состоявшийся разговор с этим номером закрывает такие задачи сам.
* `events/recording` — запись скачивается фоновым воркером в `RECORDINGS_DIR` (в prod — том `call_recordings`) и хранится 90 дней, затем удаляется.
* «📞 Позвонить» в сделке и карточке контакта — `commands/callback`: АТС звонит менеджеру, затем соединяет с клиентом. Нужен назначенный внутренний номер.

Отчёт во вкладке «Звонки»: пропущенные, ожидающие перезвона, время разговоров и ожидания по менеджерам, журнал с записями. Тесты: `tests/test_telephony.py`.

## Качество заявок, SLA, отчёты и экран «Запуск»

* **Целевой / нецелевой.** В карточке сделки менеджер отмечает качество заявки (для нецелевой — причина). Квалификация и продажа ставят «целевой» сами. В «Аналитике» — доля целевых по каналам и кампаниям и причины нецелевых; в «Результате» — в итогах. Поле `client_leads.quality`.
* **Надёжные источники.** У источника заявок есть флаг «Сразу в сделки» (`lead_inbound_sources.auto_accept`): заявка минует «Неразобранное», повторное обращение клиента с открытой сделкой добавляется в неё. По умолчанию включён для Tilda и звонков, выключен для чатов. Настройка: «Настройки → Подключения».
* **SLA 15 минут** (`services/watchdog.py`, раз в минуту): заявка в «Неразобранном», новая сделка без первого ответа или чат без ответа дольше 15 минут → уведомление «Заявка без ответа» руководителю и ответственному. Только в рабочее время проекта (9:00–21:00 по его часовому поясу), один раз.
* **Еженедельный отчёт** в понедельник в 9:00: расход, заявки, доля целевых, цена заявки, продажи, ROMI, скорость ответа, пропущенные звонки, лучший канал, комментарий маркетолога. **Алерт по цене заявки** — ежедневно в 10:00, если CPL за 7 дней вырос больше порога (по умолчанию 30%). Получатели и Telegram настраиваются в «Настройки → Уведомления».
* **Экран «Запуск»** на странице «Результат»: чек-лист (считается автоматически), план работ агентства со статусами, карточка маркетолога, цели месяца с план-фактом. Агентство заполняет его в админке, в карточке компании. Владелец может менять цели и скрыть экран.
* Убраны дубли меню: «Продажи», «Кампании», старые списки лидов и `/portal` — они перенаправляют в CRM / «Результат».

## Бриф

Два независимых этапа, вопросы и формулы взяты из
`docs/design/express-quiz.html` и `docs/design/full-brief.html`.
Серверный справочник — `app/services/brief_schema.json`, сервис — `app.services.brief`.

### Экспресс-оценка

Публичная `/brief`: 12 вопросов, один на экран, прогресс, автопереход одиночного
выбора, «Не знаю», черновик в localStorage. Предел цены заявки =
готов отдать за клиента × покупки из 10 / 10; «6+» считается как 6 по эталону.
Неизвестные цифры не подставляются. Полоса «сейчас / предел» и до трёх рекомендаций
рассчитываются на сервере по правилам эталона, не LLM.

Настройки (только образец `.env.example`; реальные `.env` не изменяются):

- `AGENCY_WORKSPACE_ID`: ID активной компании агентства; 0 выключает приём.
- `BRIEF_PRIVACY_URL`: адрес опубликованной политики обработки данных.
  Без политики приём выключен; checkbox не заменяет сам документ.
- `BRIEF_DEMO_TTL_DAYS=14`: срок демо.
- `BRIEF_DEMO_DAILY_CAP=30`: общий лимит демо в сутки UTC; 0 отключает автоматическое создание демо.
- `BRIEF_BOOKING_URL=/contact`: ссылка на разбор в демо-баннере.
- LLM использует существующую конфигурацию `LLM_MODEL_SUMMARY` / `LLM_MODEL`;
  распознавание — существующие `STT_PROVIDER`, `STT_API_KEY`, `STT_MODEL`.

`POST /api/brief/submit` проверяет Origin, контакт, согласие 152-ФЗ, honeypot,
обязательные вопросы и лимит трёх демо с одного IP в сутки UTC.
IP хранится хешем; PostgreSQL advisory-lock сериализует допуск с одного IP.
Общий транзакционный lock защищает глобальный лимит от одновременных запросов.
При исчерпании глобального лимита заявка и оценка сохраняются без демо:
на экране «Демо-кабинет пришлёт менеджер»; такие заявки не расходуют лимит демо по IP.
Заявка создаётся через существующий `inbound_lead.create_inbound`, источник
«Экспресс-оценка», в неразобранном CRM агентства. Все ответы, расчёт, UTM и referrer
сохраняются; заявка, ExpressAssessment и персональное демо записываются атомарно.
Демо называется компанией посетителя; логин и пароль показываются только при
создании, открытый пароль не хранится. Остальные показатели демо — вымышленные.
В карточке CRM сохраняются логин демо и ссылка `/portal/reset?username=…`, но не пароль.
Ссылка предзаполняет логин; восстановление требует уже подключённого Telegram.
Если клиент не подключал бота, администратор перевыпускает доступ в карточке клиента.
Публичный квиз использует отдельные scoped-стили из `express-quiz.css`: Manrope,
синий градиент, светлая/тёмная тема. Стили портала не затрагиваются.
Фиксация точки А доступна только администратору агентства; владелец клиента
может сохранять цифры до фиксации. Проверка прав выполняется сервером.
После commit Telegram-админам отправляются имя, ниша, бюджет, предел и текущая
цена заявки, ссылка на CRM. Нужны уже привязанные Telegram-аккаунты администраторов.
`/admin/briefs` показывает экспресс-оценки с ценами и статусом CRM, ответы и полные брифы.
В оценке администратор выбирает рабочий проект и нажимает «Связать с рабочим клиентом»:
создаётся черновик полного брифа и заполняется точка А. Заявка остаётся в агентстве.
Демо-владельцу доступен экспресс-результат; полный бриф открывается в рабочем проекте.

Каждые 5 минут worker мониторинга мягко архивирует истёкшее демо через
`workspace_archive`: отключает доступ и интеграции, данные сохраняются.
Для автоматического TTL worker должен быть запущен.

### Полный бриф

Владелец клиента открывает «Настройки → Бриф», администратор — карточку клиента →
«Бриф клиента» → рабочий проект. Адрес `/brief?project_id=ID`.
10 разделов, ключи, варианты выбора и подсказки из полного эталона; ручная форма
автоматически сохраняет серверный черновик. Импортированные поля отмечены
«Заполнено ИИ, проверьте».

«Заполнить из записи встречи»: MP3/M4A/WAV/OGG до 200 МБ либо текст расшифровки.
Backend-образ включает FFmpeg: запись нормализуется в моно 16 кГц и делится
на 4-минутные WAV-фрагменты под лимит существующего STT. Не больше 4 часов.
SpeechKit/Whisper вызываются через существующий call_ai с учётом расхода.
Расшифровка сохраняется, затем один вызов LLM раскладывает её по ключам вопросов:
только факты, отсутствующие данные пустые, фразы клиента дословно.
Дополнительно сохранён импорт DOCX/PDF/MD/TXT до 5 МБ.
Без LLM заголовки «ключ: ответ» разбираются детерминированно, свободный текст
остаётся в «Что ещё нам важно знать» для ручной классификации.
Длинный вход отклоняется с понятной ошибкой, не молча обрезается.
Для длинных встреч может потребоваться увеличить `LLM_MAX_INPUT_CHARS`;
синхронная загрузка ожидает распознавание, при сетевом таймауте можно вставить текст.

Статусы: draft → review (импорт ИИ) → applied только по «Подтвердить бриф».
Ручной черновик также требует подтверждения. Подтверждение ещё не меняет ИИ.
Следом «Предпросмотр знаний ИИ» → проверка → «Применить к ИИ».
Knowledge ≤7500, tone/goal ≤300, чек-лист ≤12 пунктов, всего ≤2000 символов.
Без LLM справка собирается детерминированно; средний чек не превращается в прайс.
Запись в `project.portal_state.ai`, предыдущие значения — в `ai_history`, последние 5.
Изменение ответов отменяет подтверждение и предпросмотр; хеш защищает от применения
устаревшего предпросмотра. Чек-лист читается существующим анализом звонков
через `call_checklist`.

### Точка А и цель

Блок в карточке клиента, полном брифе и «Результате»: заявки/месяц, цена заявки,
конверсия, продажи/месяц, средний чек, бюджет, дата старта, числовая цель и метрика
на 3 месяца. Заполняется из экспресс-оценки для демо и при подтверждении полного
брифа; диапазон бюджета и текстовая цель не превращаются в выдуманное число.
До фиксации цифры редактируют владелец и администратор; фиксирует только администратор агентства.
После фиксации редактирует только администратор. Каждое изменение
пишется в `portal_state.baseline_history`. В «Результате» — текущие значения,
разница и прогресс (текущий − старт)/(цель − старт), включая цели на снижение CPL.
Месячные исходные показатели сравнивайте с полным месяцем, не с произвольной неделей.

Миграция аддитивная через `db_upgrade.py`: новая таблица `express_assessments`;
к существующей `client_briefs` добавляются `transcript` и `ai_fields` в columns.
Старые записи сохранены. Миграция выполняется при запуске backend.
Для записи встречи пересоберите backend-образ, чтобы установить FFmpeg.
Также пересоберите / перезапустите frontend: таймаут серверного прокси для долгого
распознавания увеличен до 30 минут. Обычные вызовы api() остаются с таймаутом 30 секунд.

Проверка руками:

1. Настройте ID агентства, политику, Telegram и провайдеры на своём окружении.
2. Пройдите `/brief?utm_source=website&utm_campaign=brief_test`: при 1500 ₽ за
   клиента и 2 покупках из 10 предел должен быть 300 ₽. Проверьте CRM и Telegram.
3. Сохраните выданный доступ, нажмите «Открыть демо-кабинет», войдите.
4. В рабочем клиенте откройте полный бриф. Вставьте «Мы стоматология в Самаре.
   Средний чек 5000 рублей. Клиенты говорят: “Хочу записаться без ожидания”».
   Проверьте пустые поля, расшифровку и метки ИИ. Повторите с аудиозаписью.
5. Подтвердите бриф, сформируйте предпросмотр, примените. Откройте чат →
   «Подсказать ответ»: он должен опираться на знания этой компании.
6. Укажите дату, цель и метрику, зафиксируйте точку А. Владелец больше не может
   менять её; администратор может, с записью истории. Откройте «Результат».
7. `python -m unittest discover -s tests -p test_brief.py` — тесты с моками LLM/STT;
   `python -m unittest discover -s tests` — весь набор.

## ИИ

Для Gemini бюджет генерации включает внутренние рассуждения. Минимальные бюджеты:
подсказка и кампании — 1024 токена, резюме — 2048, анализ звонка — 4096.
Это потолок расхода, не обязательный объём ответа. При `finish_reason=length`
(или `stop_reason=max_tokens`) сервис один раз повторяет запрос с увеличенным
бюджетом, максимум 8192. Если ответ снова оборван, возвращается русская ошибка,
а не успешный результат; обе попытки учитываются в расходе и дневных лимитах.
Проверки `/admin/ai` используют рабочие построители промптов и вымышленную
переписку стоматологии: консультация ещё не назначена. Они не отправляют
сообщения клиентам. Чек-лист звонка требует подтверждения всех частей пункта;
отсутствие возражений не засчитывается как их отработка. Корректный JSON не
гарантирует фактическую точность анализа: проверяйте его по расшифровке.

Текстовые функции (подсказка, резюме, анализ звонков и кампании) используют единый
`services/ai.py`. Сообщения клиентам сами по себе не отправляются при диагностике.
Кампании сохраняют существующий режим отправки и собственные настройки API.

### Подключение и модели

Настройки задаются в окружении backend (локально `.env`, на сервере `.env.prod`).
Образец — `.env.example`; ключи нельзя коммитить, публиковать в браузере или пересылать в чат.

- `LLM_PROVIDER`: `yandex`, `openai`, `anthropic`, `openai_compatible`.
- `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`: основной ключ, адрес и модель.
- `LLM_MODEL_CHAT`, `LLM_MODEL_SUMMARY`, `LLM_MODEL_CALLS`, `LLM_MODEL_CAMPAIGNS`:
  модель на функцию; пустая строка наследует `LLM_MODEL`, затем прежний провайдерный default.
- `LLM_TIMEOUT=60`: таймаут одной попытки в секундах. При 429, 5xx и таймауте —
  один повтор через секунду. Две попытки могут занять до 121 секунды.
- `LLM_MAX_INPUT_CHARS=24000`: максимум символов инструкции и истории вместе.
  Сохраняются инструкция и хвост переписки; слишком длинная инструкция тоже обрезается.
- `AI_DAILY_TOKEN_LIMIT=0`, `AI_WORKSPACE_DAILY_TOKEN_LIMIT=0`: общий и клиентский
  дневной лимит токенов по UTC, 0 отключает ограничение. Перед каждой попыткой
  резервируются оценка входа и максимальный выход; при завершении — фактический расход.
  При исчерпании провайдер не вызывается. Лимиты приблизительные: токенизатор модели
  может отличаться от оценки. PostgreSQL сериализует допуск advisory-lock'ом.
- `AI_PRICES`: JSON с ценами за миллион входящих/исходящих токенов в рублях, например
  `{"my-model": [100, 300]}`. Это ваша таблица оценки, не тариф провайдера.

Для Timeweb Gateway: `LLM_PROVIDER=openai_compatible`,
`LLM_BASE_URL=https://api.timeweb.ai/v1`; имя модели копируется из вкладки
«Подключение», ключ создаётся отдельно в AI Gateway. Наличие настроек не означает,
что ключ, баланс и доступ к модели проверены — используйте диагностику.

После изменения окружения локально: `docker compose up -d --no-deps --force-recreate backend`.
На сервере: `docker compose --env-file .env.prod -f compose.prod.yml up -d --no-deps --build backend`.
Обычный `restart` не подхватывает изменённое окружение Compose.

### Звонки и распознавание речи

`STT_PROVIDER=yandex` — SpeechKit v3, `STT_PROVIDER=openai` — совместимый
`/audio/transcriptions`. Настройки: `STT_API_KEY` (если пусто — LLM_API_KEY),
`STT_MODEL`, `STT_BASE_URL`, `YANDEX_FOLDER_ID` для SpeechKit.
`STT_RESPONSE_FORMAT=verbose_json` подходит Whisper; для моделей Timeweb
`openai/gpt-4o-mini-transcribe` задайте `json`. JSON без сегментов сохраняется одним фрагментом.
У SpeechKit асинхронное распознавание; у Whisper-совместимого API — синхронное.
Невалидный JSON анализа исправляется одним дополнительным запросом; если схема
снова не соблюдена, звонок получает `ai_status=error` с русским описанием.

### Проверка из админки

Откройте `/admin/ai` под администратором. API: `/api/admin/ai`,
`GET /api/admin/ai/usage?days=1|7|30`, `POST /api/admin/ai/test/chat|summary|calls|campaigns`,
`POST /api/admin/ai/stt` (multipart, поле `file`). Ключи в ответах отсутствуют.
Текстовые тесты используют вымышленные данные, можно выбрать компанию для учёта лимита.
Тест STT — загрузка своего WAV с русской фразой, до 60 секунд / 9 МБ,
например «Здравствуйте, это тест распознавания речи портала». Это альтернатива встроенному аудиофайлу.
Проверка кампаний здесь использует серверные настройки; runtime-ключ кампании
проверяется в самой кампании. Все проверки платные и учитываются в расходе.

В `ai_usage` хранятся функция, модель, компания, токены, длительность, секунды
аудио и безопасная ошибка, без промптов и ответов. При отсутствии usage токены
оцениваются как округлённое вверх `len(text)/3`. Повтор — отдельная запись.
У STT учитываются секунды и оценка выходного текста; цену секунд нужно сверять
с провайдером отдельно. Цены отсутствующих моделей показываются как неизвестные.
SpeechKit пишет отдельно принятие операции (секунды) и её финальный результат
(текст/ошибка); промежуточные проверки незавершённой операции не учитываются.
Периоды сегодня / 7 / 30 дней и дневные лимиты отсчитываются по UTC.
Миграция аддитивная: `db_upgrade.py` создаёт таблицу `ai_usage` (также включена
в metadata.create_all); существующие данные не удаляются.

Мониторинг сообщает в Telegram при >=5 ошибках за час или доле ошибок >50%.
Подключите Telegram администратора в `/admin/monitor`; сообщения отправляются
существующим механизмом мониторинга с подавлением повторов.
Для клиентов сохраняются тарифные ограничения `ai_chat` / `ai_calls` и права доступа.

### Слепое сравнение моделей

Из каталога backend:

```bash
python -m app.scripts.ai_eval --workspace 1 --chats 20 --calls 20 --models "m1,m2,m3"
```

В локальном Docker:

```bash
docker compose exec backend python -m app.scripts.ai_eval --workspace 1 --chats 20 --calls 20 --models "m1,m2,m3"
```

Подставьте реальные ID моделей одного настроенного провайдера. Результат:
`backend/eval_reports/<UTC-время>/report.html` и отдельный `key.json`.
Каждый кейс независимо перемешан под A/B/C; время и токены показаны рядом с буквой.
Сначала оцените ответы, затем откройте ключ. В production контейнере отчёты нужно
скопировать наружу до пересоздания контейнера (`docker cp`).
Скрипт не отправляет сообщения и не запускает кампании, но делает платные вызовы.
Звонки без записи пропускаются; без расшифровки распознаются один раз и кешируются
в существующем JSON `Call.meta.eval_transcript`. Это единственная запись в данные звонка.
Телефоны, email, Telegram-контакты и имена маскируются до отправки модели.
Эвристическая маскировка не гарантирует полную анонимность: для сравнения используйте
тестовую компанию или заранее обезличенные диалоги; не отправляйте чувствительные данные.
Распознавание записи отправляет исходное аудио STT-провайдеру; маскировка текста
выполняется уже после распознавания, перед отправкой в LLM.

Ручная приёмка: ответ-подсказка не обещает отсутствующих в знаниях условий;
резюме сохраняет факты; звонок даёт валидную схему; неверный ключ даёт русскую
ошибку; исчерпанный дневной лимит блокирует API; расход появляется в админке;
пользователь тарифа «Старт» не может вызвать ИИ чатов, «Рост» — ИИ звонков.

## Этап 2: ИИ, офлайн-конверсии, коллтрекинг, PWA, здоровье клиентов

- **ИИ в чатах.** В переписке: «✨ Подсказать ответ» и «✨ Резюме переписки» (резюме можно сохранить в сделку). База знаний, тон и цель — Настройки → Подключения → «ИИ-ассистент». Провайдер задаётся в `.env`:
  - YandexGPT (по умолчанию): `LLM_PROVIDER=yandex`, `LLM_API_KEY=<API-ключ сервисного аккаунта>`, `YANDEX_FOLDER_ID=<id каталога>`;
  - Claude: `LLM_PROVIDER=anthropic`, `LLM_API_KEY=...` (модель — `LLM_MODEL`, по умолчанию claude-sonnet-5-5);
  - ChatGPT/совместимые: `LLM_PROVIDER=openai` или `openai_compatible` + `LLM_BASE_URL`.
  Без ключа кнопки просто не показываются.
- **Офлайн-конверсии.** Квалифицированная заявка и продажа из CRM записываются как конверсии (yclid / ClientID Метрики / vkclid / телефон). Настройки → Подключения → «Конверсии в рекламу»: OAuth-токен Метрики с правом записи и номер счётчика — цели `stl_qualified` и `stl_sale` создаются сами, выгрузка раз в час. Для VK Рекламы — выгрузка CSV.
- **Коллтрекинг.** CRM → Звонки → Настройки: каждому номеру Mango привязывается канал/источник, звонок попадает в аналитику этого канала.
- **PWA и пуш.** Портал ставится на телефон («На экран Домой»), пуш-уведомления включаются в Настройки → Уведомления. На iPhone пуш работает только у установленного на экран приложения (iOS 16.4+). VAPID-ключи генерируются сами; можно задать `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT`.
- **Здоровье клиентов** — в админке клиентов: оценка 0–100 и причины (нет заявок, просрочки, SLA, рост CPL, нет подключений).

## Этап 3: разбор звонков, КП и счета, виджет, забота о клиенте, импорт amoCRM, тарифы

- **ИИ-разбор звонков.** Каждый состоявшийся звонок дольше 25 секунд с записью расшифровывается и оценивается: резюме, потребность, следующий шаг, возражения, оценка по чек-листу скрипта, совет менеджеру. Видно в журнале звонков, карточке сделки и в статистике менеджеров. Чек-лист — Настройки → Подключения → «ИИ-помощник». Распознавание речи в `.env`:
  - Yandex SpeechKit (по умолчанию при `LLM_PROVIDER=yandex`): ключ и каталог берутся из `LLM_API_KEY` / `YANDEX_FOLDER_ID`, сервисному аккаунту нужна роль `ai.speechkit-stt.user`;
  - Whisper: `STT_PROVIDER=openai`, `STT_API_KEY=...` (`STT_BASE_URL`, `STT_MODEL` — для совместимых сервисов).
- **КП и счета.** В карточке сделки блок «КП и счета»: позиции, скидки, НДС, сумма прописью, ссылка для клиента (`/d/<код>`), уведомление менеджеру при первом открытии, «Оплачен» сразу подтверждает продажу. Реквизиты — Настройки → Компания.
- **Виджет на сайт.** Аналитика → подключённый сайт → «Виджет «Перезвоните мне»»: форма обратного звонка с согласием по 152-ФЗ и кнопки WhatsApp / Telegram / MAX / телефона. Код: `<script async src="https://portal.steptolead.ru/stl-widget.js" data-stl-key="КЛЮЧ_САЙТА"></script>`. Заявки идут в CRM с UTM и yclid.
- **Забота о клиенте** (Настройки → Воронка): напоминание о встрече/замере за N часов, просьба об отзыве через N дней после продажи, задача на повторную продажу. Сообщения уходят в чат сделки с 9:00 до 21:00, иначе — задача менеджеру. По умолчанию выключено.
- **Импорт из amoCRM.** CRM → «Импорт из amoCRM»: выгрузка сделок (XLSX/CSV), предпросмотр с сопоставлением этапов и менеджеров, склейка контактов по телефону/email, успешные сделки — продажи прошлых периодов. Повторная загрузка не создаёт дублей.
- **Тарифы.** Админка → клиент → «Тариф»: Старт (до 3 сотрудников, чаты Авито и WhatsApp), Рост (до 7, все чаты, телефония, ИИ в чатах, конверсии в Метрику), Система (без лимита, ИИ-разбор звонков). Клиенты без тарифа — «Индивидуальный», без ограничений. Клиент видит свой тариф в Настройки → Компания.

## Яндекс Карты и 2ГИС (Реклама → Подключить рекламу)

У Яндекс Бизнеса и 2ГИС нет открытого API статистики, поэтому канал карт заполняется так:
- **Расход** — стоимость продвижения за месяц (подписка Яндекс Бизнеса, пакет 2ГИС), портал раскладывает её по дням; от него считаются CPL и ROMI.
- **Статистика карточки** — показы, переходы, «Позвонить», маршруты, переходы на сайт: загрузка Excel/CSV-выгрузки (Яндекс Бизнес → Статистика → загрузка у графика) или ввод цифр за месяц (2ГИС).
- **Заявки** — автоматически: звонки на номер коллтрекинга Mango, поставленный в карточку (CRM → Звонки → Настройки → привязать номер к каналу), и визиты с сайта по метке `utm_source=yandex_maps` / `utm_source=2gis` (готовая ссылка — в карточке канала).

## Запуск: мониторинг, восстановление пароля, демо-портал

- **Мониторинг** (админка → «Мониторинг»): подключите свой Telegram — портал раз в 5 минут проверяет рекламные кабинеты, чаты, телефонию, фоновые задачи, всплески ошибок и место на диске, пишет о новом сбое один раз, напоминает через сутки и сообщает «восстановлено». Нужен `TELEGRAM_BOT_TOKEN`. Выключение сервера целиком отслеживает только внешняя проверка: добавьте `https://<домен>/api/health` в UptimeRobot / Яндекс Мониторинг (проверка раз в 5 минут, ответ 200 — всё хорошо, 503 — нет базы).
- **«Забыли пароль?»** на странице входа клиента: код из Telegram-бота (сотрудник должен заранее подключить Telegram в Настройки → Уведомления). Без Telegram пароль сбрасывает руководитель или агентство.
- **Демо-портал** (админка → Клиенты → «＋ Демо-портал»): компания «Кухни «Северная»» с вымышленными данными за 4 месяца — реклама, заявки, сделки, продажи, звонки с разбором, переписка. Логин и пароль показываются один раз. Демо не синхронизируется с настоящими сервисами и не попадает в мониторинг; удаляется как обычная компания.
- **Резервные копии**: сервис `backup` в `compose.prod.yml` делает `pg_dump` раз в сутки в том `db_backups` и хранит 14 дней. Копируйте их за пределы сервера.
